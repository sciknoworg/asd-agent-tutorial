# BO-01 Implementation Note

Task ID: BO-01
Title: Add shared Bayesian-optimization interfaces and run records
Branch: `feature/bayesian-optimization`

## Scope

BO-01 adds shared infrastructure only. It does not implement Gaussian processes,
acquisition functions, Stage 1 process models, Stage 2 constrained optimization, or
hybrid LLM-BO behavior.

## Architecture Added

- `src/asd_agent/bo/interfaces.py` defines `ExperimentBackend` and `Optimizer`
  protocols.
- `src/asd_agent/bo/records.py` defines `CandidateProposal`, `OptimizerObservation`,
  `BOExperimentRecord`, `RunManifest`, `OptimizerState`, and `BORunRecord`.
- `src/asd_agent/bo/backend.py` defines `VirtualASDBackend`, which wraps
  `VirtualLab.simulate` and reuses existing safety checks.
- `src/asd_agent/bo/serialization.py` saves and restores optimizer states, BO
  experiment records, and BO run records as JSON.

The existing `ExperimentRecord` remains the canonical ledger row. BO-specific metadata
is stored in BO artifacts that wrap, rather than replace, existing records.

## Information Boundaries

Optimizer-facing records contain:

- tested condition;
- measured GA and NGA thickness;
- measured selectivity;
- process time;
- objective result and failure reasons;
- experiment timestamp.

Optimizer-facing backend context contains:

- backend name;
- scenario and description;
- objective constraints;
- safety bounds.

Hidden simulator parameters remain outside optimizer payloads:

- GA/NGA surface response parameters;
- nucleation delays;
- inhibitor sensitivities;
- measurement noise setting;
- process-time constants.

No evaluation-only oracle was implemented in BO-01.

## Remaining Limitations

- No GP model, acquisition function, or BO loop is implemented.
- Candidate IDs are collision-resistant UUID-based identifiers, not deterministic hash
  IDs.
- The `bo-gp` and `bo-ax` extras were resolver-checked but not installed or imported.
- Python 3.14 runtime compatibility remains unverified locally.
