## Current Experiment Record Format

`ExperimentRecord` contains:

- `experiment_id`
- `condition`
- `ga_thickness_nm`
- `nga_thickness_nm`
- `selectivity`
- `process_time_s`
- `meets_objective`
- `failure_reasons`
- `decision_rationale`
- `timestamp`

The nested `ExperimentCondition` contains:

- `precursor_dose_s`
- `coreactant_dose_s`
- `inhibitor_dose_s`
- `temperature_c`
- `cycles`

Ledger persistence writes:

- `experiments.json` with `ExperimentRecord.model_dump()` rows.
- `experiments.csv` with flattened condition fields and measurement fields.
- `run_metadata.json` with method, scenario, status, failure category, seed, model,
  token usage, timestamps, and full configuration.

## Current Configuration Loading Mechanism

`load_scenario(name)` resolves `configs/{name}.yaml` relative to the project root.
`load_config(path)` reads JSON-compatible YAML. It prefers `yaml.safe_load` when
PyYAML is installed and falls back to `json.loads` when PyYAML is unavailable.
The loaded mapping is validated as a `ProcessConfig`.

Current scenario configs define:

- scenario name and description
- seed
- Gaussian measurement noise
- process-time constants
- GA and NGA `SurfaceParams`
- `SafetyBounds`
- `ObjectiveConstraints`

## Simulator Entry Points

Primary simulator entry points are:

- `VirtualLab(config, seed=None)`
- `VirtualLab.simulate(condition, experiment_id, decision_rationale)`
- `VirtualLab.surface_thickness(surface_name, condition)`
- `VirtualLab.process_time(condition)`

The simulator uses seeded NumPy RNG for measurement noise. With fixed seed and
noise settings, virtual lab measurements are deterministic.

## Agent Abstractions

`OptimizationAgent` is a protocol with:

```python
next_decision(config, ledger, budget_remaining)
```

The method returns either:

- `ProposedExperimentsDecision`, containing one to four `ExperimentCondition` values
  and a concise rationale; or
- `FinishOptimizationDecision`, containing status, a tested experiment ID, and a
  concise rationale.

`run_agent_loop` validates proposed experiment safety before simulation and rejects
finish decisions that reference untested experiment IDs.

## Backward-Compatibility Risks for Future BO Work

- Changing `ExperimentRecord` would affect JSON/CSV ledgers, LLM input construction,
  benchmark summaries, and tests.
- Changing `ExperimentCondition` fields would affect configs, safety validation,
  simulator calls, plotting, baselines, and notebooks.
- Adding heavy BO imports at top level could break the no-API/no-BO tutorial path.
- Modifying `run_agent_loop` status semantics could affect rule-based and LLM agents.
- Changing `FailureCategory` or `FinishStatus` literals could break benchmark summaries
  and schema tests.
- Replacing the config loader with non-JSON YAML features could break the current
  standard-library fallback.
- Adding BO CLI behavior to existing commands without default-off gating could change
  existing demo or benchmark output.
- PyTorch-family packages may not support every declared Python target at the time a
  later stage adds them.

## Proposed BO Architecture Summary

Future BO stages should add a new BO package layer that:

- converts `SafetyBounds` into BO search domains;
- converts `ExperimentRecord` ledgers into training observations;
- keeps optional ML-library imports isolated from non-BO paths;
- proposes safe `ExperimentCondition` values;
- reuses `VirtualLab`, `validate_safety`, and existing objective helpers;
- keeps current ledgers and benchmark summaries backward-compatible;
- adds deterministic no-API BO tests before any hybrid LLM-BO stage.
